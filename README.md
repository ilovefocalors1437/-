# ระบบสื่อสารด้วยการกระพริบตา

เว็บต้นแบบสำหรับผู้ที่ไม่สามารถพูดหรือควบคุมแขนขาได้ ใช้การกระพริบตาเลือกพยัญชนะ สระ วรรณยุกต์ และข้อความด่วน เพื่อประกอบเป็นประโยคบนหน้าจอ

> สถานะ: MVP สำหรับทดลองกับผู้ใช้และเก็บข้อมูล ไม่ใช่อุปกรณ์การแพทย์ และยังไม่ควรใช้เป็นช่องทางฉุกเฉินเพียงช่องทางเดียว

## วิธีควบคุม

- แต่ละตัวเลือกมี time slot คงที่ 1.35 วินาที ระบบรวมจำนวน blink ภายใน slot แล้วตัดสินเมื่อ slot สิ้นสุด
- ไม่กระพริบใน slot: ผ่านไปตัวถัดไป
- กระพริบ 1 ครั้งใน slot: เลือกตัวปัจจุบัน แล้วเริ่ม slot ใหม่ที่ตัวถัดไป
- กระพริบ 2 ครั้งใน slot: สลับหมวด พยัญชนะ → สระ/วรรณยุกต์ → ข้อความด่วน
- หลับตาค้างประมาณ 1–4 วินาที: freeze วงล้อเพื่อพักสายตา เมื่อลืมตาจะทิ้ง gesture และเริ่ม slot ใหม่จากตัวเดิม
- หลับตาครบ 5 วินาที: หยุดกล้องและระบบเลือกทันที โดย **ไม่เลือก** ตัวอักษรที่แสดงตอนเริ่มหลับตา
- ผู้ดูแลยังสามารถกดหมวดหรือตัวอักษรบนจอเพื่อทดสอบและช่วยแก้ข้อความได้

หน้าต่างเลือกกำหนดคงที่ 1.35 วินาที และ long close กำหนดคงที่ 5 วินาที ผู้ใช้เปลี่ยนค่าไม่ได้ ไอคอนรูปหนังสือเปิดคู่มือการใช้งาน ส่วนค่าการปรับเทียบจะถูกเก็บเฉพาะใน `localStorage` ของเบราว์เซอร์

## เริ่มใช้งานในเครื่อง

กล้องของเบราว์เซอร์ต้องเปิดผ่าน `localhost` หรือ HTTPS ห้ามเปิด `index.html` ด้วย `file://` โดยตรง

```bash
python -m http.server 4173
```

จากนั้นเปิด <http://localhost:4173> กด **เปิดกล้อง** อนุญาตสิทธิ์กล้อง และกด **ปรับเทียบดวงตา** ก่อนเริ่มใช้งานจริง

รันชุดทดสอบ:

```bash
npm test
```

## หลักการตรวจจับ

เว็บใช้ MediaPipe Face Landmarker ในโหมดวิดีโอและอ่านค่า blendshape `eyeBlinkLeft` / `eyeBlinkRight` บนอุปกรณ์ผู้ใช้ ภาพจากกล้องไม่ได้ถูกอัปโหลดไป backend

ขั้นตอนลด false positive:

1. ต้องตรวจพบใบหน้าก่อน ระบบจึงจะเดินวงล้อและรับคำสั่ง
2. ใช้สัญญาณจากตาซ้ายและขวาพร้อมกัน จึงไม่ตีความการขยิบตาข้างเดียวเป็นคำสั่ง
3. ทำ exponential smoothing เพื่อลด landmark jitter
4. ใช้ threshold สองค่าแบบ hysteresis แยกจังหวะ “ปิด” และ “เปิด”
5. จำกัดช่วงเวลาของ blink ปกติที่ 90–900 ms
6. ทุกตัวอักษรใช้ scan window เดียว 1.35 วินาที ไม่เริ่ม deadline ใหม่เมื่อพบ blink
7. หากยังหลับตาอยู่ตอน window หมด ระบบจะ freeze และไม่ resolve คำสั่งจนกว่าจะลืมตาหรือครบ long close
8. การพักตาที่นานเกิน blink ปกติแต่ไม่ถึง 5 วินาทีจะยกเลิก input ใน window นั้น แล้วเริ่มใหม่จากตัวเดิม
9. long close จะยกเลิก window ที่รออยู่ ปิดกล้อง และหยุดระบบเลือกเพียงครั้งเดียว
10. tracking หลุดจะล้าง gesture ที่ค้างและหยุดวงล้อทันที

ค่าเริ่มต้นใช้ blendshape score `0–1` ของตาทั้งสองข้าง โดยถือว่าปิดเมื่อทั้งสองตาสูงกว่า `0.40` และถือว่าเปิดกลับเมื่อต่ำกว่า `0.24` เป็น hysteresis เพื่อให้การกะพริบตาเบา ๆ ถูกตรวจจับได้ง่ายขึ้นโดยไม่สั่นไปมาบริเวณ threshold การปรับเทียบจะเก็บ median ตอนลืมตา `O` และหลับตา `C` แล้วคำนวณค่าเปิดกลับเป็น `O + 0.18(C−O)` และค่าปิดเป็น `O + 0.38(C−O)` โดยต้องมีระยะห่างอย่างน้อย `0.16`

### ทำไม MVP นี้ไม่ใช้ YOLO-World

YOLO-World แบบ pretrained เป็น open-vocabulary object detector แต่ไม่มีคลาสสภาวะ “ตาเปิด/ตาปิด” ที่เชื่อถือได้โดยตรง และมีต้นทุน inference ใน browser สูงกว่า Face Landmarker มาก สำหรับโจทย์นี้ face landmarks/blendshapes ให้สัญญาณตรงกว่าและปรับเทียบเฉพาะบุคคลได้ อย่างไรก็ตาม logic ตรวจจับถูกแยกไว้ใน `src/blink-engine.js` เพื่อให้เปลี่ยนหรือเพิ่มโมเดล classifier ที่ train กับข้อมูลผู้ใช้จริงในอนาคตได้

## โครงสร้าง

```text
index.html                 UI และ accessibility structure

src/app.js                 กล้อง, MediaPipe, calibration และ UI controller

test/*.test.js             unit tests ของ gesture/interaction logic
.github/workflows/static.yml  deploy GitHub Pages เมื่อ push เข้า main
```

## การทดสอบกับผู้ใช้จริงที่ควรทำต่อ

- ปรับเทียบใหม่ทุกครั้งที่แสง มุมกล้อง แว่น หรือท่าศีรษะเปลี่ยนมาก
- เก็บ false accept / false reject แยกตามผู้ใช้ ไม่ใช้ threshold กลางเพียงค่าเดียว
- ทดลอง scan speed หลายระดับและวัดเวลาสร้างประโยค รวมถึงอาการล้าของดวงตา
- เพิ่ม dwell/refractory period หากผู้ใช้มีอาการกระพริบถี่โดยไม่ตั้งใจ
- ทดสอบกับแว่นสะท้อนแสง ตาปรือ หนังตาตก การขยับศีรษะ และกล้องคุณภาพต่ำ
- มีวิธีควบคุมสำรองสำหรับผู้ดูแล และไม่ใช้ long close เป็นคำสั่งฉุกเฉิน
